## ขอบเขตที่ต้องปรับก่อนยืนยันว่าตรงทุกข้อ

1. **DIP ใน AuthService:** [AuthService.java:25](https://github.com/leeLnwCode/CPFriendFinder/blob/b909af972f5016b20945d23aba9a9537c7ebdbe9/src/main/java/com/cp/friend/service/AuthService.java#L25) ยังประกาศ concrete UserInterestService แทน UserInterests ควรเปลี่ยน declaration และปรับ test ที่เกี่ยวข้องในรอบแก้โค้ด ไม่ได้แก้ในเอกสารรอบนี้
2. **OCP ของ resolver:** [MessageContentStrategyResolver.java:21](https://github.com/leeLnwCode/CPFriendFinder/blob/b909af972f5016b20945d23aba9a9537c7ebdbe9/src/main/java/com/cp/friend/service/strategy/MessageContentStrategyResolver.java#L21) รับเข้าเป็น MessageContentStrategy แต่ลงทะเบียนเฉพาะ implementation ที่สืบทอด AbstractMessageContentStrategy การเพิ่ม implementation ของ interface อย่างเดียวจึงยังไม่พอ ควรอธิบายข้อกำหนดนี้หรือปรับ contract ให้ resolver พึ่ง interface ได้จริง
3. **SRP ของ ChatMessageService:** มีทั้ง message CRUD, membership check, notification และ call signaling หลักฐานการแยก strategy ช่วยลดงาน แต่ไม่ใช่เหตุผลยืนยันว่า service ทุกคลาสมีความรับผิดชอบเดียวแล้ว

การใช้ constructor injection และมี interface เป็นหลักฐานการออกแบบ แต่ยังต้องอธิบายความรับผิดชอบและ contract ในการนำเสนอ ไม่สรุปว่าปราศจากการละเมิดทุกกรณีจาก annotation เพียงอย่างเดียว
